# 直播高光筛选

输入：完整转写文稿（含原片起止时间）、内容类型、目标平台；可选切片条数、时长目标、禁用内容和重点主题。
只有摘要或缺失起止时间时，先指出缺失内容，不编造原片时间戳。可接收 Whisper 的 JSON、带时间段的文本或词级转写。时间显示到毫秒不代表测量精度达到1毫秒。

## 筛选规则

1. 先识别开场试音、沉默候选、调试、无意义闲聊、重复复述、疑似口误和片尾残句，生成预处理备注。转写语音间隙不等同于已确认的声学静音。
2. 通读上下文再选段：问题有回应、观点有论据或解释，代词指代可理解。禁止把半句话、未完成推论或缺失前提的回答当成独立片段。
3. 优先级为价值输出、设问反转、观众互动爆点、情绪上扬。只见文本时，情绪只能作为文字线索，不能虚构音量或声学证据。
4. 优先选连续原片区间。若必须拼接，额外输出有序 `source_ranges`，明确说明删去的内容，不能用一个虚假的连续区间代替。
5. 按用户提供的平台和时长要求筛选。素材不够时减少数量并解释，不用重复片段凑数。评分是编辑判断，不是播放量预测。
6. `hook_sentence` 区分主播原话与编辑拟定问题：通过 `hook_type` 标记，编辑句不得冒充原音。

## 输出

输出 JSON 对象，包含 `preprocessing_notes` 和按优先级排列的 `candidates`。每条候选必须包含：

- `clip_id`：稳定且唯一的标识。
- `source_start`、`source_end`：原片时间，格式 `HH:MM:SS.fff`，开始严格早于结束。
- `hook_sentence`、`hook_type`（`source_quote` 或 `editorial`）。
- `core_content`：主要观点和解释。
- `tag`：标签数组。
- `risk_note`：已发现的确定性承诺、导流、无来源数字、语义歧义等，没有发现则说明检查范围。
- `source_text`：覆盖候选区间的完整原话，保留可能有风险的原文，供后续文本扫描使用。
- `score`：0–100编辑评分；`score_reason`：选择理由；`status`：`candidate` 或 `needs_review`。

原片时间不能混用成片时间。需要成片时间时按各段变速及顺序另算；单段的换算为 `(source_time - source_start) / speed + timeline_in`。

清单可交给编排、动画规划或素材点位规划步骤；这是数据交接，不代表自动调用其他技能。遵守当前对话的技能白名单与确认门槛，不自动安装依赖或启动剪辑。
