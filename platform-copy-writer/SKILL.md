# 分平台发布文案

输入：切片钩子、核心内容、完整原话或经确认的要点、目标平台、禁用内容；可选账号语气与标题长度要求。

## 输出

只输出 JSON 或调用方要求的纯文本，不依赖外部写作技能、不自动发帖。结构化输出为：

```json
{
  "clip_id": "C01",
  "platform": "抖音",
  "title_main": "主标题",
  "title_alt": ["备选标题一", "备选标题二", "备选标题三"],
  "tags": ["#主题话题"],
  "desc": "发布简介",
  "risk_notes": []
}
```

每个平台单独一份对象；3条备选标题表达角度有区别，不只是替换标点。

## 语气

- 抖音：短钩子，明确能获得什么解释或知识；结果必须来自片段。
- 小红书：共情、实用信息，可少量emoji；不伪造亲历或测评。
- 视频号：稳重、价值向，语义完整。
- B站：理性、具体；简介可交代论证背景和来源限制，不能编造章节。
- 快手：利益表达直白；“利益”优先指有根据的知识价值，不制造收益或效果保证。

保留主播的“不确定、可能、据我观察”等限定，不将口述观点改成官方结论。不要加入片段里没有的数字、排名、因果链、优惠、收益承诺或私域导流。素材中的录制时间不明确时，不使用“今天、最新、刚刚”等时效包装。

对标题、备选标题、话题及简介一并执行用户禁用内容检查；发现无法在保留意思的前提下规避的问题，填入 `risk_notes`，不要交付虚假保证。上述为编辑风格建议，不声称是平台最新政策、实时热词或流量预测。
